## 0. Executive Summary — What Changed vs. What Exists

The current OT module (`routes/hospital.php` §OT, `app/Http/Controllers/Hospital/OT/*`) already implements a **v1 workflow**:

```
booked → paid → in_ward → dilated → ready → operated → discharged
```

Roles: OT Receptionist (`OtBookingController`, `OtReceptionistController`), Accountant (`OtAccountantController`), OT Doctor (`OtDoctorController`), OT Assistant (`OtAssistantController`), Billing (`OtInvoiceController`, `OtDischargeController`).

The new PDF describes a **richer, 9-step clinical + financial workflow** with a dedicated **Counsellor role**, formal **consent capture**, **package cost breakdowns**, a **Ward vitals + eye-drop register**, a **pre-OT verification checklist**, **expanded lens/inventory data**, and **more discharge documents**. Most of this is a genuine gap — some of it is a partial stub already sitting unused in the DB.

**Key finding:** Two DB tables already exist but are **never read/written by any controller** — `ot_pre_op` and `ot_dilation_entries` (see `database/migrations/2025_01_02_000015_create_ot_tables.php`). These are exactly the Ward vitals + eye-drop register the PDF asks for — they just need a controller + views wired on top. Similarly, `ot_counselling` table exists but is only half-used (auto-filled by `OtBookingController@store`, no dedicated Counsellor screen, no consent/signature fields).

## 1. Phase 1 — Counsellor Module (Highest priority — biggest gap)

**Why first:** Every downstream step (Billing → Ward → OT → Discharge) in the PDF assumes counselling + consent happened first. Right now that step doesn't exist as its own screen — it's silently folded into `OtBookingController@store`, done by the receptionist, with no consent, no signature, no cost breakdown, no blood-report check.

| Item | Action |

This REPLACES `ot_lens_options` as the source of truth for lens selection in Counselling (Phase 1) and OT (Phase 4) — `ot_lens_options` can be deprecated once this ships, or kept as a lighter "favourite/quick-pick" pointer table like the eye-exam masters pattern. |
